# IT Lead Finder

Сервис для поиска заказов на сайты, Telegram-ботов, мобильные приложения, автоматизации и CRM. Рабочие данные хранятся в закрытой схеме `leadgen` проекта Supabase Postgres.

## Многопользовательский режим

Любой пользователь может открыть бота, отправить `/start` и нажать «Зарегистрироваться». Telegram ID становится идентификатором аккаунта; отдельный пароль бот не запрашивает. При регистрации создаются персональные настройки и тестовая подписка `stub_active`. Платёжный провайдер пока не подключён, поэтому раздел «Подписка» только показывает состояние заглушки.

У каждого пользователя свои услуги, минимальный бюджет, переключатели «Без бюджета» и «Возможные потребности», список выбранных чатов, портфолио, оценки объявлений и воронка. Новому пользователю не отправляется накопленная до регистрации история.

Карточка лида содержит кнопки «Подходит», «Реклама», «Ищет работу», «Не моя услуга», «Подготовить отклик» и «Изменить статус». Обратная связь сохраняется как измеримая статистика и сама по себе не переобучает фильтр. Статусы воронки: «Сохранён», «Написал», «Обсуждаем», «Получил заказ», «Не подошёл», «Не подходит»; для полученного заказа можно сохранить сумму сделки.

Публичный чат можно добавить по `https://t.me/username` или `@username`, если он входит в проверенный realtime-реестр. В веб-кабинете пользователь также может подключить собственный Telegram-аккаунт и выбрать супергруппы, в которых он состоит. Такой монитор получает только новые события выбранных групп; история, каналы и личные диалоги не читаются. Код и пароль 2FA не сохраняются, строковая сессия шифруется отдельным ключом сервера.

После первичного отбора отдельный набор признаков ищет описания бизнес-проблем: ручной перенос заявок, потерю лидов, отсутствие единой базы, повторяющуюся рутину и похожие сигналы. Такие сообщения помечаются как «возможная потребность», а не как подтверждённый заказ. Неизвестный бюджет не заменяется выдуманной суммой и показывается только пользователям, включившим отдельный переключатель.

## Локальный бот с кнопками

Откройте файл **«Запустить бота.command»** двойным щелчком в Finder. Если настройки ещё нет, откроется мастер ввода токена. Затем отправьте своему боту `/start` в Telegram — появится меню. Альтернативный запуск из корня проекта:

```sh
.venv/bin/python -m leadgen.app bot
```

Если уже запущена старая команда `run --send`, остановите её через Ctrl+C перед запуском нового режима. Одновременно базу обслуживает только один процесс.

Кнопки: «Начать», «Остановить», «Найти сейчас», «Объявления», «Услуги», «Бюджет», «Источники», «Статус». Первый запуск — на паузе. «Найти сейчас» выполняет разовую проверку и присылает новые подходящие объявления. «Начать» включает проверку каждые пять минут. «Остановить» прекращает новые уведомления; уже начатая загрузка источников может закончиться, меню продолжает отвечать.

В многопользовательском режиме каждый зарегистрированный Telegram-пользователь управляет только своими услугами, фильтрами, чатами, обратной связью и воронкой. Настройки и положение общей очереди Telegram сохраняются в Supabase Postgres между перезапусками. Старый SQLite-режим остаётся только для изолированных тестов.

Веб-кабинет поддерживает командные пространства. Владелец приглашает администратора, менеджера или наблюдателя одноразовой ссылкой; участники работают с общей лентой, а ответственного можно назначить в карточке лида. Роли проверяются на сервере: наблюдатель не меняет данные, администратор не может изменить владельца команды.

Карточка лида показывает короткий, экспертный и дружелюбный черновики ответа. Они строятся только из исходного запроса и заполненного профиля, не отправляются автоматически и не приписывают пользователю неподтверждённый опыт. В ленте доступны массовая смена статуса, оценка качества, назначение ответственного и теги.

Уведомление содержит короткую выжимку задачи, направление, бюджет, температуру лида, понятные причины оценки и кнопку «Открыть оригинал». Горячий лид получает 70–100 баллов, тёплый — 45–69, холодный — до 44. Баллы дают явный запрос исполнителя, подходящая услуга, бюджет, срок, срочность, контакт и подробности. Самореклама и вакансии снижают оценку и отсекаются фильтром.

Меню работает через long polling, без сервера и входящих портов. Окно терминала должно оставаться открытым, компьютер не должен спать. Обычный бот не может читать произвольные группы, поэтому чтение групп выполняет отдельная MTProto-сессия вашего Telegram-аккаунта. Бот автоматически запускает её после однократной настройки.

MTProto-монитор принимает только новые сообщения в реальном времени из публичных групп, в которых подключённый аккаунт уже состоит. Он не обходит реестр, не загружает историю, не открывает личные диалоги и не читает каналы. Это исключает тысячи последовательных API-запросов и связанные с ними длительные ограничения Telegram. Чтобы источник работал, вступите в него этим аккаунтом; сообщения, опубликованные до вступления или во время остановки сервера, не восстанавливаются.

В реестр попадают только чаты из разделов «Потенциальные клиенты» и «Партнёры и заказы». Включаются только источники, которые повторная проверка признала активными. Недоступные, неактивные и личные аккаунты сохраняются с причиной, но не мониторятся.

## Что подключено в конфигурации

FL.ru, Freelance.ru, Workspace и публичные Telegram-каналы `job_developer`, `frilans`, `freelancetaverna`. Статусы и причины исключения остальных источников — в [отчёте](leadgen/research/MARKET.md) и [sources.json](leadgen/sources.json).

Биржи и несколько публичных каналов читаются без аккаунта. Для массового чтения групп нужен API ID и API Hash с `my.telegram.org`, а также вход в ваш аккаунт. Сессия хранится только локально в `leadgen/data`.

## Подключение чтения групп

Получите API ID и API Hash на `my.telegram.org`, затем откройте **«Настроить чтение Telegram.command»**. Мастер локально запросит API ID, API Hash, телефон и код Telegram. Секреты не выводятся и сохраняются в `.env` с правами `0600`.

После настройки перезапустите **«Запустить бота.command»**. Сообщения из подходящих групп, в которых аккаунт уже состоит, поступают в реальном времени. Автоматическое массовое вступление в группы не выполняется из-за лимитов Telegram и риска блокировки аккаунта.

## Подключение бота

В Telegram создайте отдельного бота через официальный `@BotFather`, командой `/newbot`. Токен вводится локально скрытым вводом, отправлять его в переписку не нужно.

Из корня проекта:

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m leadgen.app setup
```

Мастер проверит бота, предложит отправить ему `/start` и выбрать ваш чат. Он сохранит `.env` с правами `0600`. Используйте отдельного бота без работающего webhook или другого обработчика `getUpdates`.

В этом рабочем каталоге окружение `.venv` уже установлено, достаточно последней команды.

## Подключение Supabase

В рабочем запуске обязательна переменная `DATABASE_URL`. В Supabase откройте **Connect → Session pooler**, скопируйте строку подключения и добавьте `?sslmode=require`. Session pooler подходит для серверов с IPv4. Пароль базы и полную строку подключения нельзя публиковать или добавлять в Git.

Схема хранится в `supabase/migrations/20260929134042_create_leadgen_schema.sql`. Она закрыта для `anon` и `authenticated`; бот подключается напрямую к Postgres. Для однократного переноса прежней локальной базы используется:

```sh
.venv/bin/python scripts/migrate_sqlite.py --dsn "$DATABASE_URL"
```

Старый SQLite-файл после проверки переноса нужен только как резервная копия. Рабочий бот его не использует.

## Проверка и запуск

```sh
# Однократный сбор без отправки сообщений:
.venv/bin/python -m leadgen.app scan

# Статистика источников и базы:
.venv/bin/python -m leadgen.app status

# Подходящие и требующие проверки объявления, JSON Lines:
.venv/bin/python -m leadgen.app export

# Непрерывный сбор и отправка в ваш чат каждые 5 минут:
.venv/bin/python -m leadgen.app run --send
```

Остановка — `Ctrl+C`. На Mac процесс работает, пока компьютер включён, не спит и команда запущена. Для круглосуточной работы предусмотрен запуск на Linux-сервере с Docker. На сервер нужно безопасно скопировать `.env` и файл `leadgen/data/telegram_reader.session`:

```sh
docker compose up -d --build
docker compose logs --tail 100
docker compose down
```

Том `leadgen/data` сохраняет MTProto-сессию Telegram. База и настройки находятся в Supabase. Контейнер запускается непривилегированным пользователем, автоматически перезапускается и проверяет соединение с базой раз в минуту.

## Правила отбора

- Только выбранные направления; правила словарные, без платной LLM.
- Объявления не старше 72 часов. Неизвестная дата отправляется на проверку.
- 5 000 ₽ включительно; для диапазона используется нижняя граница. Бюджет «до 30 000 ₽», несколько сумм, валюта кроме рублей и почасовая/месячная ставка требуют проверки.
- Самореклама, обучение и признаки штатной вакансии отсекаются. hh и помеченные площадкой вакансии сохраняются отдельно как `review`.
- Явные запросы без бюджета отправляются как тёплые лиды с пометкой «бюджет нужно уточнить».
- Уведомление содержит выжимку, ссылку, дату, бюджет, температуру и факторы оценки.

Настройки редактируются в `leadgen/sources.json`. Изменения вступают в силу после перезапуска. hh — дополнительный адаптер, выключенный по умолчанию: для него укажите `HH_USER_AGENT` (имя приложения и контактную почту), включите источник; результаты будут в `review`, поскольку зарплата не равна стоимости заказа. Его сетевой вызов в этой среде не проверен.

## Надёжность и границы версии

Повторное чтение того же URL не создаёт новое уведомление. Нормализованные точные копии текста с тем же бюджетом подавляются между источниками; перефразированные дубли могут пройти. Неоднозначная отправка после обрыва соединения помечается `uncertain` и не повторяется автоматически — проверьте Telegram и экспорт базы. HTTP 429 оставляет сообщение в очереди с задержкой. Перед отправкой ещё раз проверяется свежесть.

Ошибка одного источника не останавливает остальные; `status` показывает время последней проверки и успех/ошибку. Диагностика доступна локально и в Docker-логах, отдельные уведомления о сбое источника в Telegram пока не реализованы.

Сервис читает первую страницу лент (при проверке: 30/25/10 объявлений на биржах и 20 сообщений на канал). Полного охвата рынка и восстановления пропущенной истории после долгого простоя нет. Пока он выключен, заказы могут уйти за пределы страницы. Тексты карточек бирж иногда сокращены, окончательные условия нужно смотреть по ссылке. Изменение HTML, ограничения доступа и капча требуют обновления адаптера; обход блокировок не реализован.

Словарные фильтры могут пропускать подходящие запросы и ошибаться в сложных формулировках. Первую неделю после запуска полезно сверять `export` с источниками и уточнять словари. Автоматических откликов заказчикам нет.

## Проверка кода

```sh
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m leadgen.app scan --fixtures --db /tmp/leadgen-check.sqlite
```

Тесты покрывают денежные форматы, вакансии и рекламу, свежесть, выжимку и температуру лида, реестр источников, дубли, очередь и карточку уведомления.
