# Сигналид

Подписочный сервис (signalid.ru). Внутренние имена `leadgen`/`leadfinder` в коде, путях сервера и systemd оставлены, чтобы не ломать развёрнутые установки.

Сервис для поиска заказов на сайты, Telegram-ботов, мобильные приложения, автоматизации и CRM. Рабочие данные хранятся в закрытой схеме `leadgen` проекта Supabase Postgres.

## Многопользовательский режим

Любой пользователь может открыть бота, отправить `/start` и нажать «Зарегистрироваться». Telegram ID становится идентификатором аккаунта; отдельный пароль бот не запрашивает. При регистрации создаются персональные настройки и пробный период `trial` на 7 дней (миграция `20261003120000_subscription_trials.sql`). Аккаунты, созданные раньше, сохраняют `stub_active` без срока. По окончании срока бот перестаёт присылать лиды, а кабинет открывает только раздел «Подписка». Платёжный провайдер пока не подключён: тариф продлевается вручную — обновите `subscriptions.status='active'`, `plan_code` и `ends_at`. Тарифы и цены — в `leadgen/billing.py`.

У каждого пользователя свои услуги, минимальный бюджет, переключатели «Без бюджета» и «Возможные потребности», список выбранных чатов, портфолио, оценки объявлений и воронка. Новому пользователю не отправляется накопленная до регистрации история.

Карточка лида содержит кнопки «Подходит», «Реклама», «Ищет работу», «Не моя услуга», «Подготовить отклик» и «Изменить статус». Обратная связь сохраняется как измеримая статистика и сама по себе не переобучает фильтр. Статусы воронки: «Сохранён», «Написал», «Обсуждаем», «Получил заказ», «Не подошёл», «Не подходит»; для полученного заказа можно сохранить сумму сделки.

Публичный чат можно добавить по `https://t.me/username` или `@username`, если служебный аккаунт сервиса уже подписан на него (такие чаты перечислены в «Каталоге чатов» кабинета). В веб-кабинете пользователь также может подключить собственный Telegram-аккаунт и выбрать супергруппы, в которых он состоит. Такой монитор получает только новые события выбранных групп; история, каналы и личные диалоги не читаются. Код и пароль 2FA не сохраняются, строковая сессия шифруется отдельным ключом сервера.

После первичного отбора отдельный набор признаков ищет описания бизнес-проблем: ручной перенос заявок, потерю лидов, отсутствие единой базы, повторяющуюся рутину и похожие сигналы. Такие сообщения помечаются как «возможная потребность», а не как подтверждённый заказ. Неизвестный бюджет не заменяется выдуманной суммой и показывается только пользователям, включившим отдельный переключатель.

## Локальный бот с кнопками

Откройте файл **«Запустить бота.command»** двойным щелчком в Finder. Если настройки ещё нет, откроется мастер ввода токена. Затем отправьте своему боту `/start` в Telegram — появится меню. Альтернативный запуск из корня проекта:

```sh
.venv/bin/python -m leadgen.app bot
```

Если запущена отладочная команда `run --send` (см. «Проверка и запуск»), остановите её через Ctrl+C перед запуском бота. Одновременно базу обслуживает только один процесс.

Кнопки меню: «Мониторинг: вкл/выкл», «Последние 5», «Услуги и бюджет», «Кабинет», «Подписка», «Помощь». Выключенный мониторинг прекращает новые уведомления, меню продолжает отвечать.

В многопользовательском режиме каждый зарегистрированный Telegram-пользователь управляет только своими услугами, фильтрами, чатами, обратной связью и воронкой. Настройки и положение общей очереди Telegram сохраняются в Supabase Postgres между перезапусками. Бот работает только с PostgreSQL; SQLite используется лишь в изолированных тестах и для офлайн-проверки `scan --fixtures`.

Веб-кабинет поддерживает командные пространства. Владелец приглашает администратора, менеджера или наблюдателя одноразовой ссылкой; участники работают с общей лентой, а ответственного можно назначить в карточке лида. Назначенный участник получает уведомление в Telegram, а дашборд показывает распределённые лиды и заказы. Роли проверяются на сервере: наблюдатель не меняет данные, администратор не может изменить владельца команды.

Карточка лида показывает короткий, экспертный и дружелюбный быстрые шаблоны, а по кнопке создаёт три персональных AI-оффера через Groq `openai/gpt-oss-120b`. Результат сохраняется вместе с расходом токенов и никогда не отправляется заказчику автоматически. При ошибке Groq быстрые шаблоны остаются доступны. Для каждого проекта можно задать отправителя, предложение, подтверждённые кейсы, вопрос, подпись, запрещённые фразы и предельную длину. В ленте доступны массовая смена статуса, оценка качества, назначение ответственного и теги.

Публичный API и webhook временно выключены: без `INTEGRATIONS_ENABLED=1` их маршруты отвечают 404, события не ставятся в очередь и не доставляются, а раздел скрыт из меню. Таблицы и данные сохранены. После включения владелец или администратор команды создаёт API-токен только для чтения либо для чтения и изменения CRM. Webhook отправляется через постоянную очередь, подписывается HMAC-SHA256 и повторяется после временной ошибки. Разрешены только публичные HTTPS-адреса на стандартном порту; переходы на локальные сети и HTTP-редиректы не выполняются.

Раздел «Спрос» считает реальные запросы текущей команды за 7, 30 или 90 дней: направления, прямые и потенциальные потребности, температуру, дни недели и часы публикации. Отчёт не смешивает данные рабочих пространств и не выдаёт выборку за оценку всего рынка.

Уведомление содержит короткую выжимку задачи, направление, бюджет, температуру лида, понятные причины оценки и кнопку «Открыть оригинал». Горячий лид получает 80–100 баллов, тёплый — 50–79, холодный — до 49. Баллы дают явный запрос исполнителя, подходящая услуга, бюджет, срок, срочность, контакт и подробности. Самореклама и вакансии снижают оценку и отсекаются фильтром.

Меню работает через long polling, без сервера и входящих портов. Окно терминала должно оставаться открытым, компьютер не должен спать. Обычный бот не может читать произвольные группы, поэтому чтение групп выполняет отдельная MTProto-сессия вашего Telegram-аккаунта. Бот автоматически запускает её после однократной настройки.

MTProto-монитор принимает только новые сообщения в реальном времени из публичных групп и каналов (с @username), на которые подписан служебный аккаунт. Такие чаты автоматически добавляются в реестр с пометкой `joined` («подписан служебный аккаунт») и не отключаются повторными проверками. Монитор не загружает историю и не открывает личные диалоги; закрытые чаты без @username игнорируются, чтобы их содержимое не уходило всем клиентам. Чтобы источник работал, подпишитесь на него этим аккаунтом; сообщения, опубликованные до подписки или во время остановки сервера, не восстанавливаются. Монитор сам переподключается после сбоев (5 с → 5 мин, FloodWait — сколько просит Telegram) и раз в минуту пишет heartbeat: блок `telegram_reader` в `python -m leadgen.app status` и на странице `/admin`.

Включены (`enabled=1`) только чаты, на которые подписан служебный аккаунт: их показывает «Каталог чатов» в кабинете и считает `telegram_enabled` в `status`. Импортированный каталог («Потенциальные клиенты», «Партнёры и заказы») хранится как справочник: проверка публичных страниц (`verify-sources`) обновляет статус и аудиторию, но ничего не включает. Активный чат каталога, на который подписан служебный аккаунт, она не включает, а отправляет на модерацию (`status='moderation'`, `enabled=0`) в ту же очередь, что и новые чаты монитора. Так же поступает чат, выключенный ранее с причиной «служебный аккаунт не подписан», если аккаунт на него подписался. Отклонённые (`rejected`) и выключенные администратором чаты проверка не трогает. Остальные строки сохраняются с причиной («служебный аккаунт не подписан», недоступен, неактивен, личный аккаунт) и не мониторятся. После подписки аккаунта новый чат попадает в реестр при синхронизации диалогов (при подключении и раз в час) или с первым новым сообщением, но не включается сам: он ждёт модерации (`status='moderation'`, `enabled=0`) в разделе «Новые чаты на модерации» на `/admin`. Сообщения из него не принимаются, пока администратор платформы не нажмёт «Одобрить» (`active`, `enabled=1`); «Отклонить» оставляет чат выключенным (`rejected`), и повторно в очередь он не попадёт. Отключённые администратором или реестром чаты монитор тоже никогда не включает обратно.

## Что подключено в конфигурации

FL.ru, Freelance.ru, Workspace и публичные Telegram-каналы `job_developer`, `frilans`, `freelancetaverna`. Статусы и причины исключения остальных источников — в [отчёте](leadgen/research/MARKET.md) и [sources.json](leadgen/sources.json).

Биржи и несколько публичных каналов читаются без аккаунта. Для массового чтения групп нужен API ID и API Hash с `my.telegram.org`, а также вход в ваш аккаунт. Сессия хранится только локально в `leadgen/data`.

## Подключение чтения групп

Получите API ID и API Hash на `my.telegram.org`, затем откройте **«Настроить чтение Telegram.command»**. Мастер локально запросит API ID, API Hash, телефон и код Telegram. Секреты не выводятся и сохраняются в `.env` с правами `0600`.

Если код входа не приходит (часто при входе с серверного IP), используйте вход по QR-коду: `python -m leadgen.app setup-telegram --qr`. Команда печатает QR в терминале; отсканируйте его в Telegram служебного аккаунта: «Настройки → Устройства → Подключить устройство». При включённой двухэтапной проверке будет запрошен облачный пароль. Новая сессия заменяет отозванный файл `leadgen/data/telegram_reader.session`.

После настройки перезапустите **«Запустить бота.command»**. Сообщения из подходящих групп, в которых аккаунт уже состоит, поступают в реальном времени. Автоматическое массовое вступление в группы не выполняется из-за лимитов Telegram и риска блокировки аккаунта.

## Подключение бота

В Telegram создайте отдельного бота через официальный `@BotFather`, командой `/newbot`. Токен вводится локально скрытым вводом, отправлять его в переписку не нужно.

Из корня проекта:

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m leadgen.app setup
```

Мастер проверит бота, предложит отправить ему `/start` и выбрать ваш чат. Он сохранит `.env` с правами `0600`. Используйте отдельного бота без работающего webhook или другого обработчика `getUpdates`.

В этом рабочем каталоге окружение `.venv` уже установлено, достаточно последней команды.

## Подключение Supabase

В рабочем запуске обязательна переменная `DATABASE_URL`. В Supabase откройте **Connect → Session pooler**, скопируйте строку подключения и добавьте `?sslmode=require`. Session pooler подходит для серверов с IPv4. Пароль базы и полную строку подключения нельзя публиковать или добавлять в Git.

Схема хранится в `supabase/migrations/20260929134042_create_leadgen_schema.sql`. Она закрыта для `anon` и `authenticated`; бот подключается напрямую к Postgres. Для однократного переноса прежней локальной базы используется:

```sh
.venv/bin/python scripts/migrate_sqlite.py --dsn "$DATABASE_URL"
```

Старый SQLite-файл после проверки переноса нужен только как резервная копия. Рабочий бот его не использует.

## Проверка и запуск

```sh
# Однократный сбор без отправки сообщений:
.venv/bin/python -m leadgen.app scan

# Статистика источников и базы (число лидов в Postgres — приблизительное, по pg_stats; --exact — полный подсчёт, медленно):
.venv/bin/python -m leadgen.app status

# Проверка живости воркера по heartbeat (код выхода 0/1; используется как Docker healthcheck):
.venv/bin/python -m leadgen.app healthcheck

# Подходящие и требующие проверки объявления, JSON Lines:
.venv/bin/python -m leadgen.app export

# Отладка без бота: непрерывный сбор и отправка подходящих объявлений каждые 5 минут
# только в чаты из TELEGRAM_CHAT_ID / TELEGRAM_NOTIFY_CHAT_IDS (фильтры из sources.json):
.venv/bin/python -m leadgen.app run --send
```

`run --send` — однопользовательская отладочная команда: она не учитывает пользователей, проекты и подписки многопользовательского режима. Для работы сервиса используйте `bot`; одновременно запускать `run --send` и `bot` на одной базе нельзя.

Остановка — `Ctrl+C`. На Mac процесс работает, пока компьютер включён, не спит и команда запущена. Для круглосуточной работы предусмотрен запуск на Linux-сервере с Docker. На сервер нужно безопасно скопировать `.env` и файл `leadgen/data/telegram_reader.session`:

```sh
docker compose build
docker compose run --rm --no-deps leadfinder python -m leadgen.web_migrate  # до запуска нового кода
docker compose up -d --wait
docker compose logs --tail 100
docker compose down
```

Миграции нужно применить до старта нового воркера: код читает новые колонки (например, `user_preferences.delivery_cursor`). `deploy/leadfinder-update.sh` делает это в том же порядке.

Том `leadgen/data` сохраняет MTProto-сессию Telegram. База — сервис `db` (Postgres 17 в томе `pgdata`, пароли в `.env.db`) в `compose.yaml`; переезд с Supabase, резервные копии и откат описаны в `DEPLOY.md`, раздел 16. Перед `run --no-deps … web_migrate` база должна работать: `docker compose up -d --wait db`. Контейнер запускается непривилегированным пользователем и автоматически перезапускается; healthcheck раз в 30 с проверяет свежесть heartbeat воркера (`healthcheck`).

Необязательные переменные `.env` (секунды):

- `WORKER_HEARTBEAT_MAX_AGE` — после какого возраста heartbeat воркер считается зависшим, по умолчанию 300.
- `LEAD_DELIVERY_MIN_SECONDS` — минимальный интервал между проходами доставки лидов, по умолчанию 5 (0–300).
- `LEAD_DELIVERY_IDLE_SECONDS` — проход доставки не реже этого интервала, даже без новых лидов, по умолчанию 30 (1–3600).
- `LEAD_CURSOR_LAG_SECONDS` — насколько старым должен быть лид, чтобы курсор доставки пользователя прошёл его, по умолчанию 600 (60–86400).
- `LEADGEN_MIGRATE_*` — `web_migrate` при занятых блокировках: `LOCK_ATTEMPTS` (5), `RETRY_BASE_SECONDS` (2), `RETRY_MAX_SECONDS` (30), `LOCK_TIMEOUT` (15s), `STATEMENT_TIMEOUT` (120s), `CONCURRENT_LOCK_TIMEOUT` (60s), `CONCURRENT_STATEMENT_TIMEOUT` (0 — без ограничения) для `CREATE INDEX CONCURRENTLY`.

## Правила отбора

- Только выбранные направления; правила словарные, без платной LLM.
- Объявления не старше 72 часов. Неизвестная дата отправляется на проверку.
- 5 000 ₽ включительно; для диапазона используется нижняя граница. Бюджет «до 30 000 ₽», несколько сумм, валюта кроме рублей и почасовая/месячная ставка требуют проверки.
- Самореклама, обучение и признаки штатной вакансии отсекаются. hh и помеченные площадкой вакансии сохраняются отдельно как `review`.
- Явные запросы без бюджета отправляются как тёплые лиды с пометкой «бюджет нужно уточнить».
- Уведомление содержит выжимку, ссылку, дату, бюджет, температуру и факторы оценки.

Настройки редактируются в `leadgen/sources.json`. Изменения вступают в силу после перезапуска. hh — дополнительный адаптер, выключенный по умолчанию: для него укажите `HH_USER_AGENT` (имя приложения и контактную почту), включите источник; результаты будут в `review`, поскольку зарплата не равна стоимости заказа. Его сетевой вызов в этой среде не проверен.

## Надёжность и границы версии

Повторное чтение того же URL не создаёт новое уведомление. Нормализованные точные копии текста с тем же бюджетом подавляются между источниками; перефразированные дубли могут пройти. Неоднозначная отправка после обрыва соединения помечается `uncertain` и не повторяется автоматически — проверьте Telegram и экспорт базы. HTTP 429 оставляет сообщение в очереди с задержкой. Перед отправкой ещё раз проверяется свежесть.

Ошибка одного источника не останавливает остальные; `status` показывает время последней проверки и успех/ошибку. Диагностика доступна локально и в Docker-логах, отдельные уведомления о сбое источника в Telegram пока не реализованы.

Сервис читает первую страницу лент (при проверке: 30/25/10 объявлений на биржах и 20 сообщений на канал). Полного охвата рынка и восстановления пропущенной истории после долгого простоя нет. Пока он выключен, заказы могут уйти за пределы страницы. Тексты карточек бирж иногда сокращены, окончательные условия нужно смотреть по ссылке. Изменение HTML, ограничения доступа и капча требуют обновления адаптера; обход блокировок не реализован.

Словарные фильтры могут пропускать подходящие запросы и ошибаться в сложных формулировках. Первую неделю после запуска полезно сверять `export` с источниками и уточнять словари. Автоматических откликов заказчикам нет.

## Проверка кода

```sh
.venv/bin/python -m unittest discover -s tests -v
```

Офлайн-проверка парсеров на сохранённых страницах. Сначала один раз скачайте страницы включённых источников в `leadgen/research/*.html` (папка в `.gitignore`), затем запускайте сбор без сети на отдельной SQLite-базе:

```sh
.venv/bin/python scripts/probe.py
.venv/bin/python -m leadgen.app scan --fixtures --db /tmp/leadgen-check.sqlite
```
