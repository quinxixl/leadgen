# Запуск веб-кабинета без приёма платежей

## Состояние версии

Ветка `codex/web-product` содержит работающий базовый кабинет. Она не обновляет сервер на `main`.
Вход подтверждается существующим ботом. Кабинет и бот используют одни таблицы пользователей,
лидов, настроек, обратной связи и статусов. Проекты и история требуют новой миграции.

Работают: лендинг, вход, лента и карточки, поиск, статусы, сумма сделки, обратная связь,
заметки, напоминания в Telegram с сохранением в базе, личные Telegram-подключения с выбором групп,
история изменений из кабинета, история статусов из бота, три проверяемых черновика ответа,
массовые действия, расширенная обратная связь, теги, API-токены чтения/записи,
подписанные HTTPS-webhook с очередью повторов, проекты с независимыми
фильтрами, отсутствие повторного уведомления между проектами, CSV/XLSX с фильтрами, отчёты за 7/30/90 дней, динамика лидов, качество источников,
результаты проектов и время до отметки «Написали»,
каталог источников, аналитика спроса по направлениям, времени и типу потребности,
а также просмотр диагностики администратором.

Командный режим включает пространства, роли владельца, администратора, менеджера и наблюдателя,
одноразовые приглашения, назначение ответственного по лиду, Telegram-уведомление назначенному
менеджеру и отчёт по распределённым лидам и заказам.

Черновики сейчас формируются детерминированно из сообщения и профиля без выдуманных фактов.
Ещё не входят в эту версию: AI-анализ, готовые коннекторы amoCRM/Bitrix24/Google Sheets,
ограниченный пробный период. Их нельзя рекламировать как доступные.
Текущий доступ бесплатный, без срока и платежей. На экранах нет неработающих кнопок этих функций.

## Адрес

Собственный домен не обязателен. Подойдёт технический HTTPS-адрес хостинга с обратным
прокси к порту 8000. На VPS такой адрес автоматически не появляется: нужен технический
адрес провайдера или отдельно настроенный постоянный HTTPS-прокси.
Обычный HTTP по IP для публичного входа не используйте: cookies защищены флагом Secure.
Не публикуйте базу данных, файл `.env` или Telegram-сессию.

## Настройки сервера

Сохраните резервную копию базы и текущий SHA перед переключением версии.
Используйте уже настроенный `DATABASE_URL` из `.env`.
Добавьте в `.env`:

```dotenv
WEB_SECRET_KEY=значение_сгенерированное_командой_ниже
TELEGRAM_BOT_USERNAME=имя_вашего_бота_без_символа_собаки
WEB_ALLOWED_HOSTS=ваш-технический-адрес,localhost,127.0.0.1
WEB_ADMIN_TELEGRAM_IDS=ваш_числовой_Telegram_ID
TELEGRAM_SESSION_ENCRYPTION_KEY=отдельный_ключ_шифрования_Fernet
```

Создать секрет:

```sh
python3 -c 'import secrets; print(secrets.token_urlsafe(48))'
```

Создать отдельный ключ шифрования Telegram-сессий:

```sh
python3 -c 'from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())'
```

Не меняйте этот ключ после подключения пользователей: старые сессии перестанут расшифровываться.
`TELEGRAM_API_ID` и `TELEGRAM_API_HASH` приложения также должны быть настроены на сервере.

Не добавляйте протокол, путь или порт в `WEB_ALLOWED_HOSTS`. Telegram ID администратора
задаётся только окружением сервера; пользователь не может повысить свои права через сайт.

## Сборка и миграция

После проверки версии на тестовом окружении:

```sh
cd /opt/leadfinder
git fetch origin
git switch --track origin/codex/web-product
docker compose -f compose.yaml -f compose.web.yaml build
docker compose -f compose.yaml -f compose.web.yaml run --rm --no-deps leadfinder python -m leadgen.web_migrate
docker compose -f compose.yaml -f compose.web.yaml up -d
docker compose -f compose.yaml -f compose.web.yaml ps
```

Миграцию запускайте этим способом. Не применяйте тот же SQL отдельно через панель Supabase:
повторный запуск должен видеть запись и контрольную сумму в `leadgen.web_schema_versions`.
Базовые миграции существующего бота должны быть применены заранее.
При ошибке миграции не запускайте новую версию бота: ей нужны таблицы проектов и истории.

Прокси должен передавать исходный Host и обслуживать HTTPS. Порт 8000 привязан только к localhost.
Если хостинг запускает web-контейнер отдельно, используйте команду из `compose.web.yaml`
и передайте переменные окружения. Сам бот должен оставаться постоянно работающим процессом.

## Автообновления

Для тестового сервера, который должен следить за этой веткой, добавьте к systemd-сервису:

```ini
[Service]
Environment=LEADFINDER_BRANCH=codex/web-product
Environment=LEADFINDER_WEB=1
```

После изменения выполните `sudo systemctl daemon-reload`.
Обновлятор собирает образ, применяет миграции и только потом заменяет контейнеры.
Включайте ветку разработки только на тестовом сервере до завершения списка требований.
Рабочий сервер на `main` продолжает использовать текущую версию.

## Что проверить перед запуском

- [ ] HTTPS работает; адрес входит в WEB_ALLOWED_HOSTS; секрет уникален и не в Git.
- [ ] Миграция прошла, повторный запуск не меняет схему.
- [ ] Бот и сайт используют одну базу; запущен ровно один процесс бота.
- [ ] Вход с новым Telegram-пользователем создаёт аккаунт; повторный вход открывает его же.
- [ ] Код в браузере совпадает с кодом в боте; просроченный и использованный вход отклоняются.
- [ ] Второй пользователь не видит чужие лиды, проекты, заметки и CSV.
- [ ] Блокировка пользователя запрещает вход; обычный пользователь не открывает /admin.
- [ ] Услуги, бюджет, пауза и возможные потребности сохраняются и влияют на уведомления.
- [ ] Два проекта, совпавшие с одним сообщением, не дают два уведомления.
- [ ] Личный Telegram-аккаунт подключается с кодом и 2FA; код и пароль отсутствуют в базе и логах.
- [ ] В мониторинг попадают только отмеченные супергруппы; личные сообщения, история и каналы не читаются.
- [ ] Лид из личной группы доступен только владельцу подключения; отзыв очищает сессию и выключает группы.
- [ ] Одноразовое приглашение принимается один раз; отозванная и просроченная ссылка не работает.
- [ ] Менеджер меняет лиды своей команды; наблюдатель может только читать; администратор не меняет владельца.
- [ ] После назначения менеджер получает одно уведомление; неопределённая доставка не повторяется автоматически.
- [ ] Переключение рабочего пространства не смешивает лиды, проекты, выручку и экспорт разных команд.
- [ ] Отчёт «Спрос» за 7/30/90 дней не смешивает команды и корректно показывает направления, дни и часы.
- [ ] Три черновика не содержат выдуманного опыта; массовое действие применяется только к выбранным лидам команды.
- [ ] Расширенные причины нерелевантности и теги сохраняются, удаляются и учитываются в отчётах.
- [ ] API-токен чтения не изменяет CRM; токен записи не видит другие команды; отзыв токена действует сразу.
- [ ] Webhook принимает событие с верной HMAC-SHA256 подписью; локальные IP и нестандартные порты отклоняются.
- [ ] Ошибка webhook создаёт повтор с задержкой, успешное событие не отправляется второй раз.
- [ ] Объявление подрядчика отклоняется; реальный запрос заказчика проходит.
- [ ] Статус и сумма сделки видны и на сайте, и в боте; заметка остаётся после перезагрузки.
- [ ] Напоминание приходит в указанное время; отмена работает; сбой отправки отображается без повторных дублей.
- [ ] CSV/XLSX корректно открывается в Excel; специальные формулы в тексте не исполняются.
- [ ] На телефоне нет горизонтальной прокрутки страницы, формы подписаны и доступны с клавиатуры.
- [ ] На выбранном хостинге при мобильном соединении LCP не превышает 3 с на лендинге и основных экранах.
- [ ] Нет тестовых данных, вымышленных кейсов, обещаний недоступных функций или кнопок оплаты.
- [ ] Проверены резервная копия, откат образа, журналы ошибок и сохранность Telegram-сессии.

Локальные замеры страницы не подтверждают скорость реального хостинга.
